# 5장. 저장소와 데이터 보호

[목차](README.md) · 다음: [DB](06-databases.md)

## 1. 객체·블록·파일을 구분하기

객체 저장은 키로 객체를 읽고 쓰는 방식이다. 블록 저장은 서버가 디스크처럼 사용하는 방식이다. 파일 저장은 디렉터리와 파일 인터페이스를 제공한다. 파일처럼 보이는 데이터를 담는다고 모두 같은 저장 서비스가 아니다.

| 요구사항 | 먼저 검토할 선택지 | 확인할 조건 |
|---|---|---|
| 데이터셋·이미지·모델 원본 보관 | S3 | 접근 권한·보관 기간·요청 패턴 |
| EC2 운영체제·DB 디스크 | EBS | IOPS·처리량·용량·AZ |
| 여러 Linux 실행 환경의 공유 파일 | EFS | 성능·접근 방식·요금 |
| 특정 파일 시스템 호환 필요 | FSx 계열 | 필요한 파일 시스템 종류 |
| 사라져도 재생성 가능한 임시 데이터 | 인스턴스 스토어 등 | 종료·장애 시 데이터 손실 |

## 2. S3를 읽는 단위

버킷 안의 객체에는 키와 데이터, 메타데이터 등이 있다. `models/v1/model.bin`의 슬래시는 일반적인 파일 시스템의 실제 폴더와 동일하게 해석하지 않는다. 키 접두사로 객체를 묶어 관리하는 관점으로 이해한다.

모델 서버가 정확한 키를 안다면 해당 객체 읽기 권한만 필요할 수 있다. 모든 키를 검색하는 기능까지 필요하면 목록 조회 권한을 별도로 검토한다.

S3는 객체 PUT·DELETE 등의 강한 읽기 일관성을 제공한다. 그러나 애플리케이션이나 CDN이 별도 캐시를 가지고 있으면 최신 결과가 보이지 않을 수 있다. 저장소 일관성과 외부 캐시 갱신을 구분한다.

## 3. 보관 비용의 구조

단순히 GB당 저장료만 비교하지 않는다. 저장량·요청 횟수·조회/복원 비용·최소 보관 조건·전송 비용을 함께 생각한다.

예: 매일 읽는 모델을 아카이브 계층에 넣으면 저장료가 낮더라도 조회 지연과 비용 때문에 목적에 맞지 않을 수 있다. 반대로 거의 읽지 않는 장기 보관 자료는 복구 시간이 허용된다면 아카이브 선택지가 적합할 수 있다.

Intelligent-Tiering은 접근 패턴이 변하는 자료에 검토할 수 있다. 모든 작은 파일과 모든 상황에서 자동으로 가장 저렴하다고 가정하지 않는다. 현재 적용 조건과 관리 비용을 확인한다.

## 4. 버전 관리·수명 주기·복제

버전 관리는 이전 객체 상태를 남기는 데 사용된다. 수명 주기는 저장 계층 전환·만료 정책 등을 다룬다. 복제는 다른 위치에 사본을 유지하는 요구와 연결한다.

세 기능의 목적은 다르다. 복제된 사본이 있다고 잘못된 삭제나 권한 오용에서 자동으로 보호된다고 보장할 수 없다. 필요한 경우 별도 계정·보존 제어·복구 테스트 등을 설계한다. 규정에 따라 삭제를 제한해야 한다면 Object Lock 같은 보존 기능을 검토하되 운영 요구와 모드 차이를 먼저 이해한다.

## 5. EBS와 EFS

EBS 볼륨은 AZ에 종속된다. 다른 AZ에서 복원하는 방법을 생각할 때 스냅샷 등의 복구 경로를 함께 살핀다. 모든 EBS 볼륨을 여러 인스턴스에 일반 파일 공유처럼 붙일 수 있다고 가정하지 않는다. Multi-Attach에는 유형과 애플리케이션 조건이 있다.

EFS는 공유 파일 시스템 요구에 검토한다. 애플리케이션이 POSIX 파일 접근을 필요로 하는지, 여러 실행 환경에서 같은 파일을 읽고 쓰는지 확인한다. '여러 서버가 읽는다'만으로 EFS가 정답은 아니다. S3 API로 충분한 데이터라면 객체 저장으로도 해결할 수 있다.

## 6. 복구 연습

모델 버전 B를 올렸더니 품질이 떨어졌다. 다음 정보를 기록해야 A로 돌아가기 쉽다.

1. A의 저장 위치와 버전 ID 또는 변경되지 않는 키.
2. 모델 파일 해시와 전처리 코드 버전.
3. 실행 환경·라이브러리 버전.
4. 배포 설정을 A로 바꾸는 절차.
5. 캐시를 갱신하고 정상 예측을 확인하는 방법.

파일만 되돌려도 전처리 코드가 달라졌다면 같은 결과가 나오지 않을 수 있다.

확인 문제: '공유 파일 경로가 필수'와 '모델 객체를 한 번 다운로드'는 같은 요구인가? **아니다. 접근 인터페이스와 동시 쓰기 요구가 다르다.**
