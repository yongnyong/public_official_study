# 10장. 계정 없이 하는 로컬 실습 4개

[목차](README.md)

준비: Python 3.10 이상. 추가 패키지·AWS 계정·액세스 키는 필요 없다. 아래 코드는 실제 AWS 서비스의 에뮬레이터가 아닌 원리 학습용이다. `python`이 없으면 Python을 설치한 뒤 실행하며 환경에 따라 `py` 명령을 쓸 수 있다.

## 실행

저장소를 내려받은 뒤 PowerShell에서 `cloud-study` 폴더로 이동한다.

```powershell
python examples/local_labs.py
```

네트워크 접속이나 파일 변경 없이 네 실습의 결과를 출력한다.

## 실습 1. 서브넷 크기

목표: CIDR의 전체 주소 수와 일반 AWS IPv4 서브넷의 예약 주소 차이를 이해한다.

예상: `10.0.1.0/24` 전체 256개, 일반 AWS 할당 가능 251개. `10.0.2.0/26` 전체 64개, 할당 가능 59개.

과제: 코드의 CIDR을 `/28`로 바꾸고 16개/11개인지 확인한다. IPv6에 동일한 빼기 5를 적용하지 않는다. BYOIP 등은 별도 조건이다.

## 실습 2. 중복 작업과 멱등성

목표: 같은 작업 ID가 다시 들어와도 결과를 중복 기록하지 않는 흐름을 본다.

입력: job-1, job-2, job-1. 예상: 저장된 작업은 2개, 마지막 입력은 duplicate.

한계: 메모리의 dict를 사용하는 단일 프로세스 예제다. 재시작 시 기록이 사라지고 여러 워커의 동시 실행을 해결하지 않는다. 실제 분산 시스템에서는 영속 저장과 원자적 조건부 기록, 부수 효과의 트랜잭션 경계를 설계한다.

과제: 동일 ID에 다른 입력이 들어오면 왜 충돌 오류가 필요한지 설명한다.

## 실습 3. TTL 캐시

목표: 일정 시간이 지나면 캐시를 다시 채우는 동작을 본다. 실제로 기다리지 않고 숫자로 된 가상 시간을 사용한다.

예상: t=0 miss, t=5 hit, t=11 miss. TTL=10이며 만료 시각 이상이면 만료로 처리한다.

과제: 모델 버전이 바뀌었는데 키가 입력값만 포함한다면 어떤 문제가 생길까? 입력과 모델 버전을 함께 키로 사용하도록 수정해본다.

## 실습 4. 실패 후 재시도

목표: 일시적 오류와 영구적 입력 오류를 구분한다. 예제는 두 번 일시 실패 후 세 번째 성공한다. 영구 오류는 재시도하지 않는다.

실제 시스템에서는 backoff·jitter·최대 시도·타임아웃·중복 효과를 함께 설계한다. 이 실습은 기다림 없이 순서만 보여준다.
