# 3장. VPC와 연결 문제 해결

[목차](README.md) · 다음: [컴퓨팅](04-compute.md)

## 1. 네트워크 설계의 네 질문

주소가 있는가? 목적지까지 경로가 있는가? 통신이 허용되는가? 목적지 프로세스가 응답하는가? 이 네 질문을 섞지 않으면 문제 해결이 쉬워진다.

VPC는 Region 범위이고 서브넷은 하나의 AZ에 속한다. 여러 AZ를 쓰려면 AZ별 서브넷을 구성한다. CIDR이 겹치는 네트워크를 연결하려 하면 주소 충돌 문제가 생길 수 있어 처음부터 주소 계획이 필요하다.

## 2. 공개·비공개 서브넷

공개 서브넷은 인터넷 게이트웨이로의 직접 경로가 있는 서브넷이다. 그러나 EC2가 공개 인터넷과 IPv4 통신하려면 공개 주소와 보안 설정 등도 맞아야 한다. 비공개 서브넷은 직접 인터넷 경로가 없도록 구성한다.

예시 라우팅:

| 대상 | 목적지 |
|---|---|
| 10.0.0.0/16 | VPC 내부 local 경로 |
| 0.0.0.0/0 | 인터넷 게이트웨이 또는 구성에 맞는 NAT 경로 |

`0.0.0.0/0`은 모든 IPv4 목적지에 대한 기본 경로다. 더 구체적인 일치 경로가 있으면 그 경로가 우선한다.

## 3. NAT와 엔드포인트

비공개 서버가 외부 패키지 저장소에 접속해야 한다면 NAT 경로를 검토할 수 있다. NAT는 외부 사용자가 임의로 내부 서버에 연결하게 하는 공개 API 진입점이 아니다.

S3 등 AWS 서비스에 접근하려면 서비스·요구사항에 맞는 VPC 엔드포인트도 검토한다. Gateway endpoint와 interface endpoint는 구조·지원 서비스·요금이 다르다. '엔드포인트는 전부 무료' 또는 '전부 ENI 기반'으로 외우지 않는다.

공부 예시로 AZ별 NAT를 사용하는 구성은 장애 범위와 교차 AZ 경로를 줄이는 데 도움이 될 수 있지만 비용이 늘 수 있다. 실제 제공되는 NAT 유형과 Region 지원은 최신 문서에서 확인한다.

## 4. 보안 그룹과 NACL

| 기준 | 보안 그룹 | 네트워크 ACL |
|---|---|---|
| 적용 관점 | 연결된 자원의 네트워크 인터페이스 | 서브넷 경계 |
| 규칙 | 허용 규칙 | 허용·거부 규칙 |
| 상태 추적 | 있음 | 없음 |
| 반환 트래픽 | 허용된 연결의 응답 추적 | 역방향 규칙도 고려 |

예를 들어 ALB → API → DB 구조라면 DB는 필요한 DB 포트에 대해 API 계층에서 오는 연결만 허용하도록 설계할 수 있다. DB를 전체 인터넷에 공개할 이유는 없다.

## 5. 연결 장애 진단 사례

증상: 브라우저에서 API 연결 시간이 초과된다.

1. 도메인이 의도한 주소를 반환하는지 확인한다.
2. 목적지 리스너와 인증서·포트 구성을 확인한다.
3. 라우팅과 주소 할당을 확인한다.
4. 보안 그룹과 NACL의 양방향 조건을 확인한다.
5. 프로세스가 실행되고 포트에 바인딩했는지 확인한다.
6. 로드 밸런서 상태 확인 경로가 실제 응답하는지 확인한다.

401이나 403이 왔다면 적어도 어떤 HTTP 응답 주체에는 도달한 것이다. 이때 네트워크 전체가 단절됐다고 가정하기보다 인증·인가·프록시 정책을 조사한다.

## 6. DNS·CDN·하이브리드 연결

Route 53은 DNS와 라우팅 정책을, CloudFront는 콘텐츠를 가까운 위치에서 전달하고 캐시하는 방향을 공부한다. DNS 응답을 바꿔도 캐시와 TTL 때문에 모든 사용자가 즉시 전환하지 않을 수 있다.

Site-to-Site VPN은 네트워크 간 암호화 연결, Direct Connect는 전용 네트워크 연결 선택지다. 전용 연결이라는 이유만으로 모든 구간에 암호화가 자동 보장된다고 단정하지 않는다.

VPC peering은 두 VPC 연결에 쓰며 전이적 라우팅을 자동 제공하지 않는다. 다수 네트워크 연결은 Transit Gateway 같은 허브 구성을 비교한다. PrivateLink는 서비스 접근을 제공하는 요구와 연결해 공부한다.

## 손으로 설계하기

두 AZ, 공개 ALB, 비공개 API, 비공개 DB를 그린다. 각 화살표에 포트와 허용 주체를 적고 API가 S3 모델을 읽는 경로를 추가한다. 그림에 NAT를 넣었다면 왜 필요한지도 한 문장으로 적는다.
