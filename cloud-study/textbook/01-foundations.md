# 1장. 클라우드를 이해하기 위한 기초

[목차](README.md) · 다음: [보안](02-security.md)

## 1. 내 모델을 다른 사람이 쓰게 하려면

노트북에서 `predict()`가 실행되는 것과 여러 사람이 안정적으로 사용하는 서비스는 다르다. 서비스에는 요청을 받는 주소, 실행 프로세스, 모델 저장소, 입력 검사, 접근 통제, 장애 복구가 필요하다. 클라우드 공부는 이 구성 요소를 선택하고 연결하는 공부다.

예를 들어 모델 정확도는 95%여도 서버가 꺼져 있으면 예측을 제공할 수 없다. 모델 평가는 예측의 품질을, 시스템 평가는 가용성·지연·처리량·비용을 살핀다. 두 결과를 따로 기록해야 한다.

## 2. 가상 머신·컨테이너·함수

가상 머신은 운영체제 환경을 포함해 서버를 사용하는 방식이다. 컨테이너는 애플리케이션과 의존성을 묶어 실행 환경을 옮기기 쉽게 한다. 함수 실행 서비스는 이벤트가 들어오면 코드를 실행하는 형태로 관리 부담을 줄인다.

컨테이너를 만들었다고 서버 관리가 항상 사라지는 것은 아니다. 어디에 실행하느냐에 따라 호스트 관리 책임이 달라진다. 서버리스에도 서버는 존재하며 서비스 제공자가 기반 운영의 많은 부분을 담당한다.

| 질문 | 판단 방향 |
|---|---|
| OS 수준 변경이 필요한가? | VM의 제어권 검토 |
| 실행 환경을 동일하게 배포해야 하는가? | 컨테이너 검토 |
| 짧고 독립적인 이벤트 처리인가? | 함수 실행 검토 |
| 모델이 GPU·큰 메모리·장시간 실행을 요구하는가? | 실행 환경 제약부터 확인 |

## 3. 요청 한 번이 이동하는 과정

1. 사용자가 도메인을 입력한다.
2. DNS가 연결할 주소를 찾는 데 사용된다.
3. 클라이언트가 네트워크 연결을 수립한다.
4. HTTPS라면 TLS로 상대 인증과 암호화된 통신을 준비한다.
5. HTTP 요청이 API에 전달된다.
6. API가 입력을 검사하고 모델·DB 등을 사용한다.
7. 결과와 HTTP 상태 코드를 반환한다.

DNS 문제를 모델 재학습으로 해결할 수는 없다. 어느 단계에서 실패했는지 분리하는 능력이 중요하다.

### 상태 코드 예시

- 200: 요청을 정상 처리한 예.
- 400: 입력 형식 등 잘못된 요청.
- 401: 인증이 필요하거나 인증 정보가 유효하지 않은 상황.
- 403: 요청에 대한 접근 거부.
- 404: 요청한 자원을 찾지 못함.
- 429: 요청 제한에 걸림.
- 500: 서버 내부 오류.
- 503: 일시적으로 서비스를 제공하지 못함.

상태 코드만으로 원인을 단정하지 말고 로그·요청 ID와 함께 조사한다.

## 4. IPv4와 CIDR 손계산

IPv4 주소는 32비트다. `/24`는 앞 24비트를 네트워크 부분으로 사용한다는 뜻이다. 남은 비트가 8개이므로 주소 수는 `2^8 = 256`이다.

| CIDR | 전체 주소 수 | 계산 |
|---|---|---|
| /16 | 65,536 | 2^(32-16) |
| /24 | 256 | 2^(32-24) |
| /26 | 64 | 2^(32-26) |
| /28 | 16 | 2^(32-28) |

예: `10.0.1.0/24`에는 `10.0.1.0`부터 `10.0.1.255`까지 들어간다. 일반적인 AWS IPv4 서브넷은 첫 네 주소와 마지막 한 주소를 예약하므로 할당 가능 개수는 251개다. BYOIP 등 예외는 공식 문서에서 확인한다.

직접 풀기: 일반 `/26` 서브넷의 할당 가능한 주소는? **64-5=59개.** `/24`를 같은 크기 `/26`으로 나누면 **4개**다.

## 5. 프로세스·포트·파일 권한

서버는 켜져 있어도 API 프로세스가 죽으면 요청을 처리하지 못한다. 프로세스는 실행 중인 프로그램이고 포트는 통신을 구분하는 번호다. 애플리케이션이 어느 주소에 바인딩되어 있는지도 중요하다. `127.0.0.1`에만 바인딩하면 같은 호스트에서만 접속할 수 있다.

Linux 학습 명령: `pwd`(현재 위치), `ls`(목록), `cd`(이동), `cat`(내용), `ps`(프로세스), `curl`(HTTP 요청). 처음에는 로컬 학습 파일에만 사용한다. 파일 읽기·쓰기·실행 권한과 클라우드 IAM 권한은 서로 다른 계층이다.

## 6. 시스템 지표를 읽는 법

지연은 한 요청의 완료 시간이다. 처리량은 단위 시간에 완료한 요청 수다. 동시성은 같은 순간 진행 중인 요청 수다. 평균이 낮아도 일부 요청이 매우 느릴 수 있어 p95 같은 백분위 지표를 본다.

정상 상태에서 단순 근사하면 동시 처리 수 ≈ 초당 요청 수 × 평균 처리 시간이다. 초당 20건, 평균 0.5초라면 약 10건이다. 이는 설계 감각을 위한 계산이며 버스트·재시도·대기열이 있는 시스템의 용량 보장은 아니다.
