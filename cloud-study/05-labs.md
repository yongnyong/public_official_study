# 실습과 AI 포트폴리오

## 실습 A — 로컬 모델 파일 무결성 확인 (무료, 계정 불필요)

목표: 모델 파일의 내용이 같은지 확인하는 해시 개념 이해.

1. 작업용 폴더에 비밀정보가 없는 텍스트 파일 `model-demo.txt`를 만든다.
2. 내용을 `model-version-1`로 저장한다.
3. PowerShell에서 아래를 실행한다.

```powershell
Get-FileHash -LiteralPath .\model-demo.txt -Algorithm SHA256
```

4. 해시를 기록한 뒤 파일 내용을 바꾸고 다시 실행한다.
5. 내용이 바뀌면 해시가 바뀌는지 비교한다.

기록: 경로, 버전, SHA-256, 변경 내용. 해시는 파일 내용 비교에 도움이 되지만 신뢰할 수 있는 출처나 모델 성능을 증명하지는 않는다.

## 실습 B — 권한 설계 (계정 불필요)

대상: `models/classifier/v1`이라는 논리적인 모델 객체.

| 주체 | 허용 | 불허해야 할 불필요한 작업 |
|---|---|---|
| 추론 서버 역할 | 지정 모델 읽기 | 모델 삭제·버킷 관리 |
| 배포 담당 역할 | 새 모델 업로드 | 계정 전체 관리 |
| 일반 사용자 | 예측 API 호출 | 모델 저장소 직접 수정 |

각 행을 실제 IAM 정책으로 바꾸기 전에 작업명·ARN 형식·정책 결합을 공식 IAM/S3 문서에서 확인한다. 이 표는 실행 가능한 정책이 아니다.

## 실습 C — 선택적 AWS 콘솔 실습

계정과 과금 조건을 확인한 뒤 사용자가 실행하는 절차다. 이 자료 작성 과정에서 AWS 자원은 생성하지 않았다.

1. 계정에 MFA를 설정하고 일상 작업용 접근 방식을 구성한다.
2. 현재 플랜·크레딧·요금표를 확인한다. Budget 알림은 자동 사용량 상한이 아니다.
3. 작은 학습용 파일만 사용하는 비공개 S3 버킷을 만든다. 개인정보·대회 원본 데이터는 사용하지 않는다.
4. 공개 접근 차단을 확인한 뒤 학습용 파일을 업로드한다.
5. 허가된 계정으로 조회하고 외부에 공개하지 않은 이유를 기록한다.
6. 버전 관리를 켰다면 버전·삭제 마커까지 확인해 정리한다.
7. 파일과 버킷을 삭제하고 콘솔에서 남은 자원이 없는지 확인한다. 비용 반영은 지연될 수 있다.

예상 비용은 리전·사용량·계정 조건에 따라 달라지므로 실행 전 공식 계산기로 확인한다. NAT·GPU·관리형 모델 엔드포인트는 이 입문 실습에 필요 없다.

## 포트폴리오 — 내가 학습한 분류 모델을 서비스로 설계하기

첫 목표는 로컬 실행과 설계 문서 완성이다. 실제 배포는 비용·권한 확인 후 별도 진행한다.

### 요구사항

- 입력 스키마와 유효 범위를 명시한다.
- 분류 결과에 모델 버전을 함께 반환한다.
- 잘못된 입력은 명확한 오류로 응답한다.
- 모델 파일 해시와 실행 환경을 기록한다.
- 지연·오류율·처리량을 측정한다.
- 배포 실패 시 이전 버전으로 돌아갈 절차를 문서화한다.

### 만들 문서

1. `architecture.md`: 요청 흐름, 데이터 저장, 권한, 장애 지점.
2. `api-contract.md`: 입력·출력 JSON 예시, 오류 코드.
3. `evaluation.md`: 측정 환경, 요청 수, 지연·실패 결과.
4. `operations.md`: 배포, 감시, 복구, 삭제 절차.
5. `cost.md`: 비용 항목과 사용량 가정.

### 완료 기준

- 새 사람이 문서만 보고 로컬 실행을 재현할 수 있다.
- 잘못된 입력과 중복 요청 처리 방식을 설명한다.
- 모델 정확도와 서비스 성능을 따로 평가한다.
- 실제로 실행하지 않은 클라우드 구성은 '설계'라고 명시한다.
- Git에는 키·토큰·개인정보·대회 제한 데이터·대용량 모델을 올리지 않는다.
