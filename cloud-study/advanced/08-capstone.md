# 8장. AI 추론 서비스 종합 과제

[목차](README.md)

## 상황

네가 학습한 분류 모델을 친구들이 API로 사용한다. 지금은 로컬에서 돌아가지만 트래픽 변화·잘못된 입력·모델 교체·실행 서버 장애를 견딜 설계가 필요하다.

아래 수치는 학습을 위한 가정이다. 실제 성능으로 주장하지 않는다.

- 정상 5건/초, 피크 50건/초.
- 실시간 예측 p95 목표 500ms.
- 작업 결과와 모델 버전을 추적.
- 모델 파일은 비공개.
- 긴 배치 작업은 별도 큐로 처리 가능.
- 월 운영비의 사용량 가정을 설명할 수 있어야 함.

## 1단계. API 계약

입력 예:

```json
{"request_id":"demo-001","schema_version":"v1","features":[1.2,3.4,5.6,7.8]}
```

응답 예:

```json
{"request_id":"demo-001","model_version":"release-a","label":"class-1"}
```

결정할 것: 특징 순서, 숫자 범위, 결측·NaN·무한대, 추가 필드, 요청 크기, 중복 ID, 모델 버전 고정 여부. HTTP 재시도로 같은 요청이 왔을 때 결과 계약을 설명한다.

## 2단계. 성능 측정 계획

단일 요청에서 시작해 동시성을 올린다. 워밍업 전·후를 나누고 입력 분포를 기록한다. 평균뿐 아니라 p95/p99, 오류율, CPU/GPU·메모리, 모델 로딩 시간을 측정한다.

클라이언트 자체가 병목이면 서버 용량을 과소평가할 수 있다. 로컬 시험을 실제 클라우드 네트워크 성능으로 확대 해석하지 않는다.

## 3단계. 아키텍처 후보 두 개

### 후보 A: 동기 추론

API 진입점 → 실행 서비스 → 메모리 모델. 모델 원본은 비공개 객체 저장, 필요한 이력은 DB, 로그에는 요청 ID와 실행 버전.

장점: 즉시 응답 흐름이 단순하다. 확인할 점: 시작 지연, 동시성, DB 연결, 큰 모델의 메모리.

### 후보 B: 비동기 배치

업로드 → 작업 접수 → 큐 → 워커 → 결과 저장 → 상태 조회.

장점: 긴 작업과 급증 부하를 분리할 수 있다. 확인할 점: 대기 시간, 중복, 실패·재처리, 작업 보존.

둘 중 하나가 모든 입력을 해결할 필요는 없다. 실시간과 긴 작업의 계약을 분리할 수 있다.

## 4단계. 보안 표

| 주체 | 해야 할 일 | 권한 설계 |
|---|---|---|
| 사용자 | 예측 요청 | 애플리케이션 인증·요청 제한 |
| 추론 역할 | 지정 모델 읽기 | 객체 경로와 필요한 키 사용 제한 |
| 배포 역할 | 릴리스 등록 | 업로드·검증·포인터 변경 범위 |
| 운영자 | 상태 조사 | 관찰 권한과 변경 권한 구분 |

키나 토큰을 보고서에 넣지 않는다. 정책 예시는 계정·리소스 식별자를 가상 값으로 작성한다.

## 5단계. 실패 주입을 종이로 수행

1. 모델 다운로드 실패: 준비되지 않은 서버가 트래픽을 받는가?
2. DB 지연: 예측 자체도 중단할지, 일부 이력을 비동기로 처리할지?
3. 워커 종료: 작업은 언제 다시 실행되는가?
4. 중복 요청: 결과·알림·비용은 중복되는가?
5. 잘못된 모델 배포: 어느 지표가 감지하고 어떻게 되돌리는가?
6. AZ 손실: 남은 용량으로 피크를 처리할 수 있는가?

각 질문에 '문제 없음' 대신 관찰 근거와 동작을 적는다.

## 6단계. 비용 보고서

고정비와 사용량 비례 비용을 분리한다. 정상·피크·유휴 상태를 비교한다. 로그 보관 기간, 모델 버전 누적, 외부 송신 데이터, 네트워크 중계 비용을 빠뜨리지 않는다.

실제 가격을 가져올 때 날짜·Region·서비스 옵션·단위를 기록한다. 계산기 링크만 붙이지 말고 입력한 가정을 표로 남긴다.

```text
capstone/

```

### 각 문서에 들어갈 최소 내용

- requirements: 수치 목표·범위·가정·미정 사항.
- architecture: 후보 두 개, 선택 이유, 대안이 유리한 조건.
- security: 주체·작업·자원·조건·거부 테스트.
- performance: 측정 환경·표본·지연 분포·병목·한계.
- failure-runbook: 감지·진단·복구·검증·담당 역할.
- cost-assumptions: 계산식·단위·민감도·빠진 항목.
- release-and-rollback: 모델·전처리·스키마 호환·캐시·재처리.

## 자체 평가 20점

각 항목 0~4점: 요구사항 명확성, 선택 근거, 실패 대응, 보안 경계, 검증 근거. 0=없음, 1=용어만, 2=설명, 3=구체적인 절차·조건, 4=실험 또는 검증 근거까지. 이 점수는 공식 시험 점수와 무관하다.
